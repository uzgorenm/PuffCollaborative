## Findings requiring action

1. **P1 — Real selected export and consent remain an integration blocker (Serhat/Talha/Ferit).** `contracts.prepare` trusts the caller's `sharedSessions`, `workers`, and `events` envelope when selecting the two sessions (`hackathon/flower/contracts.py:119–157`). Its role/field/size/reference filtering is useful after selection, but it does not authenticate an owner, obtain a current sharing decision, or resolve citations against the durable backend. The feature README explicitly says the current `revision` shape is provisional and no backend Flower job/report port exists (`hackathon/flower/README.md:79–90,140–143`). A caller that includes an unshared Session in `sharedSessions` can send its permitted-looking messages to remote model reasoning; the adapter has no independent way to distinguish it. Before WF02 or private-export claims, supply a trusted server-side owner-selected A/B capture, map `Event.id/seq` separately from `Thread.activitySeq`, revalidate opt-in/mute and each cited event at delivery, and inspect the actual outbound payload with synthetic private and unrelated markers. Keep the synthetic SuperGrid chain milestone distinct from that proof.

2. **P1 — Older cited evidence can be presented with a newer source revision (Ferit with Serhat's event mapping).** `prepare` accepts every retained event at or before the selected session revision (`contracts.py:153–156,179–193`); `validate_analysis` checks only membership in that retained window (`contracts.py:202–206`). `make_report` sets an awareness note's `sourceRevision` to the session's latest revision, irrespective of the cited source event revisions (`contracts.py:243–269`). In an isolated, synthetic, no-network call, I added an A revision 2 event explicitly correcting A revision 1, left the request and model citation on revision 1, and obtained a **pending** note with `sourceRevision: 2` and cited A revision `1`. The existing `test_unknown_or_stale_analysis_citation_fails` checks a nonexistent revision 2 tuple when the only event is revision 1 (`test_coordinator.py:59–70`); it does not cover a retained but superseded event. Define citation/currentness semantics with the backend owner, retain the exact cited event identity and captured activity sequence, and reject or clearly mark a contradicted finding before saving/delivery. Add a deterministic correction-after-finding test; a current source revision label alone must not make an old claim appear fresh.

3. **P1 — Local evidence files are readable beyond their owner under the current default (Ferit).** `coordinator.py:41–43,115–117,159–160` writes the selected input and SQLite ledger into `.runtime`; `transport.py:26–29,108–116` and `chain_worker.py:37–48` journal model results, the validated handoff, and report. None sets private permissions. Read-only `stat` in this checkout found `.runtime` at `drwxr-xr-x` and its existing `requests.sqlite3`, `input.json`, and `events.jsonl` at `-rw-r--r--`. The present receipt says these files hold synthetic data, so this observation does **not** establish exposure of a real private Session; it establishes unsafe defaults for future real inputs on a multiuser host. Create/check state directories with owner-only access and files with owner-only access, including SQLite sidecars and pre-existing paths; keep a caller-supplied state directory private. Add a synthetic permissions regression. Git ignore and a README example using `<private-runtime-directory>` do not enforce this boundary.

4. **P2 — A partial journal line prevents cancellation of known remote runs (Ferit).** The parent deliberately tolerates a killed writer's incomplete final line in `coordinator.journal_events` (`coordinator.py:28–38`), but `transport.cancel_runs` parses every line with an unconditional `json.loads` before contacting SuperGrid (`transport.py:137–149`). A timeout after a complete `submitted` record plus a partial final line makes the cancellation subprocess exit before `StopRun`; `coordinator.execute` suppresses that subprocess failure and correctly leaves the run unresolved (`coordinator.py:68–105`). The operator `reconcile` path invokes the same parser (`reconcile.py:26–41`). Reuse tolerant journal parsing in cancellation, preserve known run IDs, and test a complete submitted record followed by a truncated line with a fake client that observes a cancellation request. Do not label an attempted or unresolved cancellation terminal.
