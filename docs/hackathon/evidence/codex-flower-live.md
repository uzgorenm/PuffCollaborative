## C3/C8 integration mapping proposal

The current Flower input is a provisional per-session `revision` shape; it must not be populated by copying project `Event.seq` into every event or by treating it as `Thread.activitySeq`. For the real adapter, carry separate fields: `Event.id` and its project-wide `Event.seq` on every cited event; the captured `Thread.activitySeq` on each selected session as the source content revision; a separate project snapshot/replay cursor; and `WorkCard.version` for card updates. Thread-filtered events may have gaps in project sequence. The backend should resolve every cited event ID and sequence to the same authorized project and Thread, then compare the report's captured source activity sequence with the current `Thread.activitySeq` before saving a card or delivering a note. Define the meaningful event kinds with the backend owner so a copied note, acknowledgment or card projection cannot trigger another analysis loop. A stable request fingerprint should include the selected permitted evidence and captured activity sequence; unchanged evidence must reuse the recorded result.

For C8, the host's `coordinate(request, snapshot)` result and Flower run IDs need an authenticated asynchronous job/result port. Keep the Flower run IDs and task IDs distinct from backend coding `Run.id`. The server must validate opt-in, target identity, citation resolution and freshness again against current state, then record a durable note/result and a stable delivery ID. The worker can admit attributed awareness through the agreed safe-turn path only after that validation. A failed or unresolved Flower run must remain visible to the job caller and must not be reported as delivery. Serhat/Talha/Ferit still need to freeze the wire fields and authority boundary; this receipt does not assert an implemented backend adapter.
