# Coordination access

The coordination API authenticates each request against a configured roster of individual credentials. A member credential resolves to a stable `userId`. The shared OpenCode server password only protects the existing instance API and does not identify a teammate.

Project membership is stored in `coordination_membership`. The creator of a shared project is its owner. Owners can admit a seeded user through `Projects.grantMember`. Both owners and members can read project threads and comments, submit instructions, comment, request cancellation, and decide approvals. The owner role is reserved for membership changes. Runner credentials can act only on threads bound to their worker ID; callback ownership is checked against the Run by the queue and runner modules. Analysis credentials can update work cards only for an existing thread. Neither service credential can list member projects.

Each protected read checks the current membership. A project ID or thread ID in a request is a lookup key, not proof of access. Project creation checks the injected `ProjectAdmission.canShareExistingProject` port before assigning ownership of an existing OpenCode project. Thread creation verifies that the OpenCode Session belongs to the project, calls `SessionBinding.resolve` for its authoritative project and worker, then requires `SessionSelection.canShareSession` for the authenticated member and exact binding. A missing selection port denies new sharing; existing shared Thread reads still use membership. These ports need trusted server-side adapters for real creation flows. Comment authorship and shared Thread creation authorship come from the validated member context. Client-supplied author or selection fields are ignored by the service interface and must not be added to route payloads.

The roster is a development bootstrap, not an account-management API. It contains distinct usernames, Bun password hashes, and server-controlled member, runner, or analysis contexts. Tests inject known contexts and say when the event or instruction reader is a mock.
