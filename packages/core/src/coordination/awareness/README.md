# Active target awareness boundary

`CoordinationAwarenessDelivery.make` is an internal target-worker boundary. It accepts a trusted report reference and stable message ID, re-resolves both shared Threads, checks the cited content Event by ID and project-wide `seq`, compares the captured source `activitySeq` with current source content, checks the target's worker and Session binding, and requires an injected `Policy.validate` result. That policy must verify the stored analysis report, current selected sharing/topic/mute state, permitted recipients, and that the finding is informational rather than an unapproved work redirection. There is no permissive default.

When the target Session is active in this process, the boundary admits a `steer` through `SessionAwareness.admit`. Its returned `admittedSeq` proves durable admission, not transcript promotion. Query `SessionAwareness.receipt` for `promotedSeq`; inspect the later target response or artifact separately for concrete use. Exact retries with the same message ID and content return the existing receipt, including after the Session becomes idle. Changed content conflicts. The source event's project sequence and the Thread's content activity sequence are deliberately separate values.

`coordination/analysis/results.ts` supplies the durable report/delivery store and the production `Policy`; this module itself is not wired to an HTTP route. A sharing change between the policy check and Session admission is still a race to resolve at integration. No coordination Run is created here, and informational awareness grants no authority to stop or redirect either coding Session.
